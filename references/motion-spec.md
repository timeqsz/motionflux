# MotionSpec 0.1 / 实现子集

发行包的机器 schema 位于 `assets/motion-spec.schema.json`，参数与后端状态来自 `assets/catalog-index.json`。引擎与目录版本为 0.4.0，场景版本保持 0.1。本版提供 53 个原子，分 8 族；每一项的行为都是本工程自定的规格，不宣称与其他工具的同名效果等价。0.3 及更早的原子 ID 已不再可用。

## 单位与坐标

- `canvas.width/height`：整数像素，16–4096。背景及节点颜色为不透明 `#RRGGBB`，没有透明画布。
- `fps`：正整数分子、分母，有效值 1–120 fps。时间为 `frame * denominator / numerator` 秒。
- `durationFrames`：1–18000 整数帧。输出采样范围为 `[0, N-1]`。求值允许小数帧，负数钳制为 0，超过 N 钳制为 N；N 是结束边界，可用于终态检查。CLI 导出的播放器默认到 N-1 停止；网站格子、详情及网站下载的 HTML 共用向前播放策略：只含持续或与时间无关原子的场景用绝对时间演化，不重置相位；含有限动效的场景完整播放到场景末尾后用最多 200ms 的淡化衔接下一轮，不倒放、不提前截断。`evaluate(frame, { continuous: true })` 只对前一种场景开放，其 elapsed、seconds、progress 可超过片段末端；含有限动效的场景拒绝此选项。默认求值和 CLI 逐帧导出仍按原始钳制规则。
- 坐标原点为画布左上，x 向右、y 向下。`position` 是节点平移，范围 ±32768 px。节点绘制的坐标变换为 T(position) × R(顺时针角度) × S(等比倍率) × S(横纵拉伸)，即局部点先缩放、再旋转、最后平移。旋转和缩放锚点为节点局部原点；不能另设锚点。按数组顺序从前向后绘制，后面的盖住前面的；本版无父子关系、约束、相机或用户脚本。
- text 的 `position` 为第一行的**左侧字母基线**；`fontSize` 为 px，`lineHeight` 为基线间距 px。仅按 LF 显式换行，不自动折行、裁剪或压缩字号。先检查文字是否超出画布。最多 20 行、2000 个 UTF-16 代码单元；禁用 CR、tab。emoji 和缺字回退未验证，不承诺跨机器一致。
- path 的 `points` 是相对于 position 的折线，2–1000 点。`strokeWidth` 为 px，圆端点、圆连接。零总长度不绘制。可选布尔字段 `closed`（末点连回首点，默认 false）和 `fill`（以节点颜色填充而不描边，默认 false）。当前无贝塞尔曲线，曲线用足够密的折线表示。

## 字体与版本

文字节点 `font: "system"` 表示设备的系统无衬线字体，`font: "mono"` 表示设备的等宽字体；二者都不声明字体资产、不读取字体文件，是保留 ID，不能用作资产名。网站及其下载默认采用这种模式，具体字形随操作系统变化。其他 font 值引用 `assets` 中的固定字体。

`assets` 只支持 font。字体包含相对于场景 JSON 所在目录的 `assets/<filename>.otf|ttf|woff2`、SHA-256、唯一 family 和 PostScript 名称。不能使用网络 URL、绝对路径或目录穿越；当前无远程资产加载。浏览器加载前和 CLI validate/export 时校验哈希，不一致就报错。Skill 示例与 CLI scaffold 默认使用设备字体，不附带字库。需要精确跨机字形时，由宿主取得获许可的字体并固定上述字段；分发时保留该字体要求的许可证。下载的 JSON 本身不含字体。

锁定信息记录 spec、catalog、engine、renderer、噪声算法与字体哈希。浏览器/GPU 的实际版本需记录在渲染或检查报告；本版不支持自动恢复旧版本环境。保证同环境固定输入的重复取帧，不承诺跨浏览器像素一致。

## 片段与角色

所有片段必须指向已存在且类型匹配的节点。`startFrame` 非负整数；`durationFrames` 正整数；末端不得超过场景 N。片段前保持其起始值，片段后 `fillAfter: hold` 保持终值。没有可执行表达式。片段的 `params` 必须写全该原子的参数；颜色参数是 `#RRGGBB` 字符串。

每个原子的 `role` 决定求值方式。对每个节点，引擎按下面的顺序计算一帧：

1. **复制排布**（`layout`：阵列、环形、网格、镜像、跟随、拖影）按片段顺序把节点变成副本，多个排布嵌套相乘。每个副本有位置偏移、角度、缩放、镜像、延迟、透明度和排布序号；跟随者和残影共用本体的序号，排在前面先画。
2. **先后延迟**（`order`：错开、扩散、乱序）无论片段在数组中的位置，都在全部排布之后执行，给副本加延迟（帧），多个相加。
3. **时间曲线**（`timing`）给出一条从 0 到 1 的曲线。属性动画用**开始帧落在某个时间曲线片段 `[startFrame, startFrame + durationFrames)` 内**的那条曲线；没有就用 smoothstep p²(3−2p)。时间曲线本身不写任何属性，不会冲突。
4. 对每个副本，用“场景帧 − 副本延迟”作为它自己的时间，依次求值**属性动画**（`property`）、**持续循环**（`loop`）和**画面质感**（`feel`）。位移和角度相加，缩放、透明度和拉伸相乘，颜色、可见区域取后写入者，像素滤镜按片段顺序依次执行。副本最后按自己的偏移、角度、缩放和镜像摆放；镜像方向上的位移和角度取反。
5. **场景连线**（`overlay`：轨迹、连线）读取各本体副本的原点位置（轨迹还读取过去若干帧的位置），在场景坐标里画线，画在该节点的所有副本之前。

属性动画之间才有冲突：同一节点上写同一属性的属性动画可以**前后衔接**，但不能共享任何一帧，区间按 `[startFrame, startFrame + durationFrames)` 判断；重叠时报 `PROPERTY_CONFLICT`。轮流的片段中，已经开始的最晚的那个生效；都没开始时，最早的那个以其起始状态生效；片段在数组里的顺序不影响结果。衔接处不做混合，后一个片段从自己的起始值开始。循环、质感、排布、延迟、曲线和连线都不参与冲突检查。

## 输出帧

求值结果的 `nodes` 按绘制顺序列出：每个节点先是它的连线（`type: "overlay"`，场景坐标的折线图层），然后是它的每个副本。副本与节点同 `id`，用 `copy` 字段区分。每个副本帧带有：

- `position`、`rotation`、`scale`、`stretch`（横纵拉伸，负值为镜像）、`opacity`、`color`。
- `pieces`（可选）：只画这些区域。每个 piece 是若干区域的并集，加上画面位移 `offset`（px）与 `shift`（以对象包围盒宽高为单位）和透明度。区域按对象自己的包围盒描述：`box`；`inset`（四边按比例内缩）；`half`（沿 `angle` 方向，从包围盒后沿 0 到前沿 1，取 `at` 之前的部分）；`band`（同一方向上 `from`–`to` 之间的条带）；`circle`（圆心按比例，半径 1 正好盖住最远的角）。空数组表示不画。文字的包围盒由渲染器按实际字形测量。
- `filters`：对这个副本画出来的覆盖率依次做的像素处理，单位为场景 px：`blur`、`glow`、`grain`、`dissolve`、`glitch`、`directional`（沿方向的运动模糊）、`split`（色散：一红一青两层在两侧，墨色在上）。
- 文字：`lines`，每行有 `text`、`y`、`opacity`，逐字原子还有 `glyphs`（每个字的 `dx`、`dy`、`opacity`、`scale`，字的位置先按整行排版再加偏移）。
- 图形：`layers`，若干组节点局部坐标的形状，可带裁剪多边形；`visiblePoints` 是描线后的可见折线。

## 各族要点

- **属性**：`prop.move` 沿 `angleDeg` 方向从 `fromPx` 移到 `toPx`（0° 向右、90° 向下）；`prop.rotate`、`prop.scale`、`prop.opacity` 从起始值到结束值；透明度和颜色在曲线冲过头时钳制在范围内。`prop.color` 在线性光下混合。`prop.blur` 是高斯模糊半径。`prop.morph` 把轮廓按弧长重采样后逐点过渡到目标形状，并选择总位移最小的起点。`prop.draw` 按弧长描线，`trailRatio > 0` 时起点跟在终点后面。`prop.crop` 从中心或一侧展开可见范围。
- **节奏**：曲线首末值精确为 0 和 1。弹簧为 1 − (1−p)²·e^(−damping·p)·cos(2π·oscillations·p)；回弹为一次下落加若干次高度按 `decay` 递减的抛物线；过冲为 back 曲线；预备为 cubic-bezier(0.45, −2.2·amount, 0.25, 1)；步进为 floor(p·steps)/steps。
- **循环**：都是时间的闭式函数，片段开始时偏移为 0（波动除外：一排副本从第一帧起就排成一条波）。漂浮与闪烁的随机只由种子、节点、片段和副本序号决定。
- **转场**：`mode: "in"` 从不可见到完整，`"out"` 把同样的画面倒过来，从完整到消失。翻转写 `stretch`，侧面朝前时为 0；推入让内容在自己的包围盒里滑过一个盒子的长度；溶解按固定随机阈值逐颗出现。
- **文字**：逐字、逐行的片段时长包含错开时间；解码从前往后依次定格；打字匀速出字，光标在打字时常亮、打完后按频率闪烁；计数把文字里的第一个 `#` 换成数字，没有 `#` 时整段文字就是数字。
- **质感**：运动模糊读取副本在快门时间内走过的距离（360° 为一整帧），静止时不模糊；颗粒和故障按各自频率换一组随机值。
- **生成**：粒子每个寿命周期重生一次，换新方向和速度，`count` 是同时在飞的数量；碎裂按片段的线性时间炸开，不受时间曲线影响；波纹是轮廓本身放大淡出；轨迹画出过去 `lengthFrames` 帧走过的路线；连线按顺序或按距离连接副本。

## 校验与交付

结构 schema 之外还校验重复 ID、资产引用、目标类型、帧范围、错开有效时长、属性写入冲突、有限数字。未知字段直接报错，不能把未支持行为偷偷带入场景。

`validate` 校验结构与字体文件；`sample` 只进行数值求值，不读取或证明字体。`preview` 和 `export-html` 生成同一种独立 HTML。输出时间轴可播放、拖动；内嵌当前场景与自有实现，无网站域名依赖。

`frames` 与 `render` 用本机已有的 Chromium 系浏览器无界面打开同一份独立 HTML，按整数帧号逐帧求值并读回 PNG，不依赖播放时钟。`frames` 写出 `frame-%06d.png`；`render` 把同样的 PNG 依次交给 ffmpeg 编码，只做编码与封装，不使用 ffmpeg 的任何画面滤镜。格式由扩展名决定：`.mp4` 为 H.264 yuv420p，`.mov` 为 ProRes 4444，`.webm` 为 VP9；`.mp4` 与 `.webm` 要求画布宽高为偶数。`--transparent` 时不绘制 `canvas.background`，PNG、MOV、WebM 带 alpha，MP4 拒绝。编码后用 ffprobe 读回帧数、时长、尺寸和 alpha 并与预期比较，结果在返回的 `verified` 中；没有 ffprobe 时 `verified` 为 false。输出没有音轨。

`scaffold <id>` 把该原子的标准示例（含它搭配的其他原子与辅助线）按给定画布与时长换算成新场景：位置与点按 `min(宽/640, 高/400)` 缩放并居中，单位为 px 的参数同比缩放，单位为 frame 的参数按时长比例缩放，再夹到各自范围内。它是起点，不保证构图合适。

本版只有 Canvas 2D，像素处理在 CPU 上逐帧计算；没有 SVG/WebGL、媒体解码、音频、图片或视频节点。浏览器与 ffmpeg 只在 `frames`、`render` 时需要，不影响检索、校验、数值求值与 HTML 预览。
