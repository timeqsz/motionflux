# 从需求到可继续修改的结果

这条流程在调用本 Skill 的 Agent 中完成。网站只展示能力和示例，不提供在线生成服务。自然语言由 Agent 理解；`search` 是关键词检索，`deliver` 是校验和打包工具，都不是语言模型。

以参考视频为输入时，先按 [视频动效拆解](video-breakdown.md) 识别动效对象、追踪动作并保留源时间码，再映射实现方式。只要求分析就停在拆解交付（拆解表与拆解动图）；要求制作时将观察到的对象与动作关系作为下面流程的输入，推测参数留作待校准项。

## 按动效对象组织作品

所有制作默认按「对象 → 对象的动作 → 对象之间的编排」组织，包括从描述新建、参考改编和后续修订。这里的元素是承载动效的对象，原子是实现动作的工具。

- **按可独立控制的粒度确定对象。** 一段整体移动的文字是一个对象；文字随后缩放、淡出仍沿用同一 ID。两段文字同时使用位移动效仍是两个对象。只有需要单独运动、替换或修改的部分才拆为子对象；逐字效果可由文字原子内部处理，不要求机械地给每个字建节点。
- **先明确对象，再选动作。** 对每个对象确定 ID、内容／素材、父组与绘制层级、初始状态，以及入场、变化、停留、退场或结尾保持。静态对象明确保持状态即可。复杂片段在项目说明中保留紧凑对象表；简单任务直接由场景节点和轨道表达，不另造重复参数文件。
- **动作绑定对象，组合使用分组。** 使用 node ID 作为 clips／animations 的 target；需要共同变换的对象进入 group，需要独立运动时保留子对象控制。位移、缩放和透明度等动作分别编排，不能因换了动效就丢失对象身份。原子缺失时使用关键帧或自定义实现，仍保留对象及其职责。
- **保持对象可修改。** 需要独立控制的文字、图片和图形保留独立节点，不在制作时合成进同一张不可拆的图片。用户提供的整张图片可以作为一个对象，无需拆解其中的物理零件。自定义宿主／Three.js 模块也保留相应的具名对象和可编辑参数；当前 custom 节点只暴露模块声明的参数，不能声称内部对象已自动成为 MotionSpec 节点。
- **按对象验收，再看整体。** 对照对象安排检查有无遗漏或重复、动画是否绑定正确、组与子对象是否同步、位置／层级是否正确、阅读与结尾状态是否完整；再完整播放检查动作承接。修订只改目标对象及必要的关联动作，保留其稳定 ID 和其他对象的保存值。此项由 Agent 核对，现有 CLI 校验不能自动证明创作对象已经全部列出。

例如「让标题从左进入，停留后缩小上移，同时产品出现」：标题始终是 `headline`，产品是 `product`；标题的位置与缩放轨道绑定同一标题对象或其布局组，产品的出现动作绑定产品对象。用到几个原子不会改变这两个对象的身份。

## 一次生成

1. **确定结果。** 从当前上下文取用途、主体与文案、画幅、时长、结尾状态和交付格式。缺少会改变结果的信息才提问；可合理默认的项简短说明。用户说“做出来”时，不要把选择原子的工作交回去。
2. **把意图变成行为。** 先按上面的对象约定确定元素与分组。多主体组合再按 [模式检索与改编](patterns.md) 筛选用途、主体、画幅，读取少量匹配项；说明采用的动作关系及内容适配，再按 [品牌与编辑约定](brand-and-controls.md) 应用项目规则。无适用模式、单个动作和局部修订沿用基础流程。按 [意图映射](intent.md) 确定各对象的动作、时间和约束，再检索短关键词并读取少量 `describe`。选择以实现需求为准，不为覆盖原子而堆效果；组合示例用于理解接口，不限定最终构图。现有原子不支持的行为要明确指出，不能默默换成相近动作。
3. **选执行方式。** 常见二维内容使用 [MotionSpec 0.2](scene-02.md) 的文字、图片、曲线、分组和关键帧；需要 Three.js 或自定义画面时用[独立模块](render-modules.md)，暴露可编辑参数并遵守逐帧准备和释放协议。已有网页可继续由宿主承载。保留场景与模块源码，不能只交一张图或成片。
4. **构建并检查。** 按对象安排建立节点与动作绑定，明确入场、阅读停留、注意力转移和落定；模式改编尤其检查新文案、素材比例和画幅。二维按 [场景编排](composition.md) 写源文件，校验引用、参数、时间与属性冲突，逐对象核对后检查整体播放及关键帧；具体视觉规则见 [quality](quality.md)。有问题就改源文件、重建并重查受影响部分。
5. **交付可运行版本。** 返回预览或约定的视频、可编辑源文件，以及实际检查范围。视频仍须编码与成片检查，HTML 不代替 MP4。素材许可说明随实际素材补齐。

二维 HTML 交付可以直接打包：

```sh
node scripts/motion.mjs deliver work/scene.json --out work/v1
```

`v1/` 包含 `scene.json`、可离线打开的 `preview.html`、声明的字体/图片/模块资产及 `delivery.json`；有 study 时还包含证据原记录与绑定报告。报告记录版本、文件哈希、边界取帧检查；`visualReview`、`browserPlayback` 初始均为 `not-performed`，`videoDelivered` 为 `false`。Agent 另记真实浏览器检查，不把工具报告里的“未检查”改成无证据的“通过”。素材许可不会被推测或自动补齐。

## 用户接着说“改一下”

- 以已交付的源文件为基线，保留稳定的节点和片段 ID。先明确本次变化与应保留的部分；例如“慢一点”改时间及错峰，“回弹轻一点”改幅度和阻尼，不重做文案和构图。
- 有 authoring.json 时运行 `controls authoring.json --scene scene.json`，读取当前保存值和驱动轨道；直接修改场景，保留稳定 ID 与无关值。compose 只用于新建，不能重建替换已有调整。
- 修改后使用新目录，工具不会覆盖旧交付：

```sh
node scripts/motion.mjs deliver work/revised.scene.json --out work/v2 --previous work/v1/scene.json
```

有编排上下文时追加 `--authoring work/v1/authoring.json`。工具验证绑定后一起打包；该文件不保存第二份参数值，也不代表参数面板已实现。

- `delivery.json` 的 `revision.changes` 按节点／片段 ID 列出字段前后值，另列绘制顺序变化。核对有没有超出要求的改动；若有就修正。数值差异不证明视觉变好，仍需查看修改段及前后衔接。
- 保留上一版作为可恢复基线。交付新结果，并简短说清“改了什么、保留了什么、检查了哪里”。

自定义宿主沿用同样的源文件保留和视觉检查原则。deliver 的数值检查不执行 custom 模块；含模块的场景必须额外真实渲染，不能把数值报告当作 GPU 或画面验收。
