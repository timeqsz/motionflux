# 从需求到可继续修改的结果

这条流程在调用本 Skill 的 Agent 中完成。网站只展示能力和示例，不提供在线生成服务。自然语言由 Agent 理解；`search` 是关键词检索，`deliver` 是校验和打包工具，都不是语言模型。

以参考视频为输入时，先按 [视频动效拆解](video-breakdown.md) 建立带源时间码的观察与原子映射。只要求分析就停在拆解交付（拆解表与拆解动图）；要求制作时将已确认的动作关系作为下面流程的输入，推测参数留作待校准项。

## 一次生成

1. **确定结果。** 从当前上下文取用途、主体与文案、画幅、时长、结尾状态和交付格式。缺少会改变结果的信息才提问；可合理默认的项简短说明。用户说“做出来”时，不要把选择原子的工作交回去。
2. **把意图变成行为。** 按 [意图映射](intent.md) 拆出对象、动作、时间和约束，再检索短关键词并读取少量 `describe`。选择以实现需求为准，不为覆盖原子而堆效果；组合示例用于理解接口，不限定最终构图。现有原子不支持的行为要明确指出，不能默默换成相近动作。
3. **选执行方式。** 二维文字／折线场景用 MotionSpec；图片、视频、三维和已有网页由宿主承载主体，再应用支持的原子属性。不要把图片、分组或三维字段塞进二维 MotionSpec。保留 Agent 编写的场景或宿主源码，不能只交一张图或成片。
4. **构建并检查。** 二维按 [场景编排](composition.md) 写源文件，校验引用、参数、时间与属性冲突。打开结果检查完整播放及关键帧；具体视觉规则见 [quality](quality.md)。有问题就改源文件、重建并重查受影响部分。
5. **交付可运行版本。** 返回预览或约定的视频、可编辑源文件，以及实际检查范围。视频仍须编码与成片检查，HTML 不代替 MP4。素材许可说明随实际素材补齐。

二维 HTML 交付可以直接打包：

```sh
node scripts/motion.mjs deliver work/scene.json --out work/v1
```

`v1/` 包含 `scene.json`、可离线打开的 `preview.html`、源文件所需的字体资产（如有）及 `delivery.json`。报告记录版本、文件哈希、边界取帧检查；`visualReview`、`browserPlayback` 初始均为 `not-performed`，`videoDelivered` 为 `false`。Agent 另记真实浏览器检查，不把工具报告里的“未检查”改成无证据的“通过”。字体许可不会被推测或自动补齐。

## 用户接着说“改一下”

- 以已交付的源文件为基线，保留稳定的节点和片段 ID。先明确本次变化与应保留的部分；例如“慢一点”改时间及错峰，“回弹轻一点”改幅度和阻尼，不重做文案和构图。
- 修改后使用新目录，工具不会覆盖旧交付：

```sh
node scripts/motion.mjs deliver work/revised.scene.json --out work/v2 --previous work/v1/scene.json
```

- `delivery.json` 的 `revision.changes` 按节点／片段 ID 列出字段前后值，另列绘制顺序变化。核对有没有超出要求的改动；若有就修正。数值差异不证明视觉变好，仍需查看修改段及前后衔接。
- 保留上一版作为可恢复基线。交付新结果，并简短说清“改了什么、保留了什么、检查了哪里”。

自定义宿主沿用同样的生成、源文件保留和视觉检查原则，但当前 `deliver` 只接收二维 MotionSpec，不能把它的检查报告套用到其他宿主。
